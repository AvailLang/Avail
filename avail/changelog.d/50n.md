### VM and optimizer

- Each generated L2 class has a package of its own, `avail.optimizer.jvm.generated.<module>.<line>_<function> (<n>)`, with its debug files in the matching directory under `debug/jvm`; a switch selects Java-identifier names instead (avail-50n)
- A JVM debugger with `debug/jvm` as a source root steps through generated L2 classes in their L2 listings, which are written as Kotlin sources (or, optionally, Java sources) declaring the class (avail-50n)
- Generated L2 classes name their register locals (`r0`, `i1`, …) for debuggers when JVM debugging is enabled (avail-50n)
- The deep manifest consistency check is off by default

### Build, distribution, and tooling

- The shared IntelliJ run configurations run on JDK 26
